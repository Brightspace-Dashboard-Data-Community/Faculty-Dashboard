YuJa Panorama faculty training

Step-by-step tutorials for using Panorama in D2L after Your Institution’s July 2026 switch from Ally. Work through them in order the first time; use individual modules as a quick reference later.

Ally is retired

As of July 2026, course accessibility scoring, remediation, and student alternative formats are provided by YuJa Panorama, not Ally. Look for the Panorama accessibility icon next to Content items.

1. Open Accessibility Reports in D2L

About 5–10 minutes. Learn where Panorama lives in Content and how to read a score.

  1. Log into D2L and open the course you want to improve.
  2. Go to Content and locate a document or page (PDF, Word, PowerPoint, Excel, HTML topic, and similar).
  3. Click the accessibility icon (or accessibility score) next to the item to open the Accessibility Report.
  4. Note the document’s accessibility score. Click View All Issues to see each issue that contributes to the score.
  5. For any issue, click Fix Issue to read a short summary of the problem and how Panorama recommends resolving it.

Tip: After a course scan completes, scores appear next to files and custom pages. If you do not see an icon yet, wait for processing or confirm the file type is supported.

Source: Getting Started with Panorama for Instructors in D2L

2. Guided Remediation

About 15–20 minutes. Fix issues one at a time with Panorama’s suggestions, then apply the updated file to your course.

  1. Open the file’s Accessibility Report.
  2. On the main issues page, click Fix This Document.
  3. Choose Guided Remediation With Assistance.
  4. Review the first issue. Use the left/right arrows or the dropdown in the top menu to move between issues if needed.
  5. Optional: check Add change to all instances of this issue to apply the same fix everywhere that issue type appears in the document.
  6. Click Update Fix to accept Panorama’s suggestion (or your edit), or Skip This Issue to move on. Use the dropdown beside Skip to Dismiss Issue when appropriate.
  7. When you have worked through the issues, review your fixes in the dropdown menu, then click Apply Fixes to Document.
  8. Panorama replaces the previous file in your D2L course with the remediated version.

When to use this: Best when you want control over each change, or when AutoPilot is unavailable for a particular issue.

Sources: Getting Started (D2L) · Resolving accessibility issues

3. AutoPilot AI remediation

About 10–15 minutes. Let Panorama propose AI-assisted fixes for supported files (PDF, DOCX, PPTX, and HTML), then review before applying.

  1. In Content, click the accessibility icon next to the document.
  2. Open the Accessibility Report.
  3. From Fix This Document, choose AI-Assisted Remediation With AutoPilot—or select AutoPilot from the report if that option is shown.
  4. Wait while AutoPilot identifies and proposes fixes.
  5. Review proposed fixes (often under a Fixes or Update Document area).
  6. If the suggestions look correct, click Apply Changes (or the equivalent apply control) so the course file updates.

Important: Always skim AutoPilot suggestions before applying—especially for headings, alt text wording, and table structure. Institution settings may limit AutoPilot by role.

Source: Using Panorama’s AutoPilot Remediation

4. Structural Remediation

About 10–20 minutes depending on the file. Use when Panorama flags tagging, reading order, or related structure problems—common on PDFs and some PowerPoint files.

  1. Open the Accessibility Report for the document.
  2. Choose Edit Structure With Structural Remediation from Fix This Document, or locate the Structural Remediation banner and click Launch.
  3. For incorrect or missing tags on a PDF: use Retag PDF to rebuild structure for the whole file, or Retag Zone to fix a selected region, then save.
  4. For reading order issues (PDF or PPTX): drag elements into a logical order that matches how a sighted reader would move through the page or slide, then save.
  5. Return to the report, confirm the score improved, and address any remaining content issues with Guided Remediation or AutoPilot.

When to use this: Scanned/untagged PDFs, heading structure that does not start at level 1, nested heading problems, and reading-order failures often need Structural Remediation (sometimes marked with an asterisk on YuJa’s checklist).

Sources: Incorrectly tagged PDF · Reading order issues · Retagging PDF elements

5. Alternative formats for students

About 5–10 minutes. Alternative formats are generated automatically; you do not need to create them manually.

  1. Open the Accessibility Report for a document in Content.
  2. Click Alternative Formats.
  3. Preview or generate a format you want to understand (students use the same menu from their view).
  4. Confirm that alternative formats are enabled for the file (they are on by default). To turn them off for a specific document, use the toggle at the bottom of the report.

Common student formats

  • PDF, Text, EPUB, Source file
  • Immersive Reader & Gradient Reader
  • Audio podcast / OCR audio
  • Braille (grade 2)
  • Enhanced HTML
  • Language translation (100+ languages)

Specialized options

  • OCR tagged PDF, DOCX, HTML, or plain text
  • Math: LaTeX, Math Text, Math Audio, MathML

Faculty tip: Improving the source file’s accessibility score usually improves the quality of alternative formats as well. Tell students that formats are available from the accessibility tools on course files.

Source: Getting Started — Accessing Alternative Formats

6. Common issues checklist

About 10–15 minutes to review. These are high-impact checks Panorama runs (aligned with WCAG and YuJa’s accessibility checklist). Fixing them early—while authoring—reduces remediation time later.

All major file types

  • Document has a meaningful title
  • Images have alternative descriptions (or are marked decorative when appropriate)
  • Contrast between text and background is sufficient
  • Tables include a header row when they present data
  • Document language is set correctly when flagged

PDFs

  • File is tagged (not a raw scan)
  • Not encrypted or corrupted
  • Heading structure starts at level 1 and nests properly
  • Reading order matches visual order
  • Scanned content has OCR / text layer

Word / DOCX

  • Real heading styles (not bold alone)
  • Descriptive hyperlink text
  • Lists use list formatting
  • Font size not below ~9 pt
  • Avoid justified text when flagged

PowerPoint

  • Every slide has a title
  • Alt text on informative images
  • Check reading order of objects
  • Sufficient contrast on themes

Excel

  • Workbook / sheet title set
  • Text present in cell A1 when required
  • Table headers defined
  • Alt text on charts/images

HTML / D2L pages

  • Meaningful alt text (not file names or placeholders)
  • Headings nested correctly; page has headers
  • Tables have headers, captions, and scope where needed
  • Videos have captions when Panorama can check them
  • Links have descriptive text; target size adequate

Full matrix (severity by issue and remediation tool): Panorama’s Accessibility Checklist
